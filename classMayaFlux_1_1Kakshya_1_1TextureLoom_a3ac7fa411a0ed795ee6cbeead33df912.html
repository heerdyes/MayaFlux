◆ create_2d_uninitialized()

std::shared_ptr< Core::VKImage > MayaFlux::Portal::Graphics::TextureLoom::create_2d_uninitialized ( uint32_t width,
uint32_t height,
ImageFormat format = ImageFormat::RGBA8,
uint32_t mip_levels = 1 )
nodiscard

Allocate a 2D texture without uploading data or transitioning its layout - left VK_IMAGE_LAYOUT_UNDEFINED.

Every create_2d*() overload above performs (and blocks on) an initial layout transition or upload of its own, even when called with no data - create_2d(w, h, format, nullptr) still does a blocking transition to eShaderReadOnlyOptimal before returning. Use this instead when the caller is about to record its own upload right after (e.g. upload_data(image, data, size, staging, true) with deferred=true), so the whole undefined -> transfer-dst -> copy -> shader-read sequence is recorded once into a deferred command batch instead of paying for a separate blocking queue.waitIdle() first.

Parameters
widthWidth in pixels.
heightHeight in pixels.
formatImage format (default RGBA8).
mip_levelsNumber of mipmap levels (1 = no mipmaps).
Returns
VKImage with device memory allocated, still in VK_IMAGE_LAYOUT_UNDEFINED, or nullptr on failure. The caller owns transitioning it before use.
